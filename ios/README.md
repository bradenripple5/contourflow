# Contour Flow — iOS wrapper

A thin native shell around `contourflow.html`. The page itself is unchanged: it
is bundled as a resource and loaded in a `WKWebView`, so the camera and
microphone work exactly as they do in Safari, minus the browser chrome.

Two pieces make it work:

- **`LocalServer.swift`** serves the bundle over `http://127.0.0.1:<random port>`.
  `file://` is not a secure context in WKWebView, so `navigator.mediaDevices`
  simply does not exist there. Loopback *is* a secure context, so `getUserMedia`
  works.
- **`WebViewController.swift`** grants the capture request in
  `WKUIDelegate.webView(_:requestMediaCapturePermissionFor:...)`. Without that
  delegate method, WKWebView denies camera and mic silently and the page only
  sees a `NotAllowedError`.

It also sets `AVAudioSession` to `.playAndRecord` / `.measurement`, which turns
off the voice-processing DSP that otherwise high-passes the microphone and
strips the bass the pattern mode reacts to.

## Layout

```
ios/
  project.yml                 XcodeGen spec (Info.plist lives here too)
  sync-web.sh                 copies ../../contourflow.html into the bundle
  ContourFlow/Sources/        App.swift, WebViewController.swift, LocalServer.swift
  ContourFlow/Web/            generated by sync-web.sh, gitignored
  ContourFlow/Assets.xcassets app icon
```

The `.xcodeproj` is generated, not committed — delete and regenerate it freely.

## Build on a Mac

```bash
brew install xcodegen
./ios/sync-web.sh
cd ios && xcodegen generate && open ContourFlow.xcodeproj
```

Then set your team under *Signing & Capabilities* and run on the phone. Re-run
`./ios/sync-web.sh` after every edit to `contourflow.html`.

## Build the IPA in CI

`.github/workflows/ios-ipa.yml` runs on `macos-15` on every push that touches
`contourflow.html` or `ios/`. It builds with signing disabled and uploads
`ContourFlow-unsigned-ipa` to the run's Artifacts.

Manually: *Actions → Build unsigned IPA → Run workflow*.

## Install with a free Apple ID

1. Download and unzip the artifact to get `ContourFlow-unsigned.ipa`.
2. Install [Sideloadly](https://sideloadly.io) on macOS or Windows.
3. Plug in the iPhone, unlock it, tap *Trust*.
4. Drag the IPA into Sideloadly, enter your Apple ID, press Start. Sideloadly
   registers the device UDID, re-signs the app and installs it.
5. On the phone: *Settings → General → VPN & Device Management →* your Apple ID
   *→ Trust*.
6. *Settings → Privacy & Security → Developer Mode →* on, then reboot and
   confirm.

The build is valid for 7 days. Re-run Sideloadly with the same IPA (or use
SideStore on-device refresh) and the camera/mic grants survive, because iOS
keys privacy decisions to the bundle ID and the re-sign uses the same Team ID.

## Run it in the cloud (no Mac)

The same workflow has a `simulator` job. It builds for the iOS Simulator, boots
one on the runner, installs and launches the app, then uploads:

- `simulator-screenshot.png` — the app running
- `simulator-log.txt` — the app's console output
- `ContourFlow-simulator.zip` — the simulator `.app`, ready for Appetize

Upload that zip at <https://appetize.io/upload> to tap through the app in a
browser. Appetize accepts simulator `.app` bundles, not `.ipa` files; the free
plan is 2 devices, 30 minutes a month, 3-minute sessions.

The simulator has no camera, so `getUserMedia({video: true})` fails there and the
app shows its camera-failure overlay. That still confirms the loopback server,
the secure context and the page load, but the camera pipeline itself needs the
physical phone.

## Notes

- Free-Sign limits: 3 apps installed at once, 10 App IDs per week, 7-day expiry.
- The bundle identifier is `com.contourflow.app` in `project.yml`. Change it if
  Sideloadly complains that the ID is already taken.
- Camera and mic still need a tap to start — that is an iOS restriction, not
  something the wrapper can bypass. The app already shows the
  "Turn Camera On" prompt in that case.
- Capture stops when the app is backgrounded or the screen locks.
- The app's "AI stems" link points at `http://127.0.0.1:8765/`, which needs the
  Python helper on a computer. There is no such backend on the phone, so that
  feature stays unavailable inside the wrapper. The wrapper's own server picks
  an ephemeral port, so the two never collide.
